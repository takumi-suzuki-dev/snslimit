資料＝`docs/sources/claude-code-usage/` の01〜07（日付不明）。README の扱い方どおり、**公式ドキュメントで今も正しいと確認できたものだけ**採用し、固定ブロックと衝突するものは除いた。
公式＝code.claude.com/docs の Best practices／Memory／Skills／Permission modes（10/18に確認）。

## 採用案

|---|---|---|---|---|

## 除外したもの（理由）
- **auto mode／許可を求めないモード（バイパス・skip permissions）**（03、06）：固定ブロックの manual mode と衝突
- **「このプロジェクトでは今後確認しない」を選ぶ**（07）：安全ルールと衝突
- **3〜4セッションを同時に動かす**（05）：「差分は1ファイルずつ」「同じフォルダで同時に動かさない」と衝突
- **広告での需要検証・CPA・PMF**（04）：固定ブロックの対象外（差別化の検証・収益化）
- **Vercel・Netlify・Supabase・Playwright**（01、02、07）：Web前提。iPhone の端末内MVPには当てはまらない
- **「コンテキスト40%を超えると劣化」**（03）：公式に数値はない（「埋まるほど劣化する」とだけある）
- **「自動で進めるモードはMaxプラン限定」**（03）：公式と食い違う。公式では v2.1.283 以降、ターミナルと VS Code では auto が初期値（10/13・10/18にauto modeで始まった理由と一致。デスクトップアプリでの扱いは未確認）
- **エラーはそのまま貼ってClaudeに聞く**（02）：単独では採用しない。CLAUDE.md「学び方」の手順2（本人が手がかりを1つ書いてから）の後に、全文を貼る形でだけ使う

## 保留（必要になったら確認）
- 起動時の auto mode を防ぐ設定（公式：`permissions.defaultMode` を manual にする）。デスクトップアプリで効くかは未確認。入れるなら**設定の永続化＝止まれ対象**
