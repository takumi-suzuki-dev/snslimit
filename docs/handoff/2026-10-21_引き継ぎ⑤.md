# 引継ぎメモ：SNS制限アプリ（構想の解像度を上げる段階）

最終更新：2026-10-21
段階：やりたいことの定義中。機能の絞り込みはまだしない
別チャットで行うこと：競合分析（3C・SWOTなど）

## 前提
- 個人開発のiPhoneアプリ
- 開発環境：手元はWindowsのみ、端末はiPhone SE（iOS 26）、Apple Developer Program加入済み

## 現在の定義（本人の発言、2026-10-20に修正）
- スタンス：SNSは使って全く問題ない。問題はアルゴリズムに飲み込まれること
- 飲み込まれやすい場面（本人の場合）
  - 嫌なことがあり、気分が落ちた時の現実逃避
  - 疲れて帰宅した時
  - 勉強に疲れた時、勉強の休憩時間
- やりたいこと：「今何をしなければならないか」という現実を本人に理解させ、自分の意思で抜けられるようにする
- 想定対象：予定が詰まっていてやることが多いのに、現実を見られていない社会人

## 引き継いでいる方針（2026-10-20時点の本人発言。新しい定義と矛盾しない範囲で有効）
- 強制力は使わない
- 10秒待ちのような「中身のない摩擦」は使わない。目的入力やAIのような「考えさせる摩擦」で筋を通す
- ポモドーロは時間の仕組みではなく「区切りごとに目的を決める行為」のイメージ。もっと良い単位があれば変えてよい
- 募金は、コアを壊さないなら導入する。ただし強制・外発的動機と衝突する可能性が高く、現時点では保留

## 定義変更で生じた構造の変化（Claudeの整理。本人の確認待ち）
- 介入のタイミングが「開く前」から「飲み込まれている最中」に移る。ゴールは「開かせない」ことではなく「抜けられる」こと
- 旧仮説「開く瞬間に、事前に宣言した目的を見せる」は主軸ではなくなる可能性がある

## 未解決の論点（Claudeによる吟味。いずれも推測を含む）
1. 「現実を見せれば抜けられる」は場面によって効き方が違う可能性がある
   - 勉強の休憩中：「休憩は終わり、次は○○」で戻りやすい。仮説が最も成り立つ
   - 疲れて帰宅：見せるべき現実は、タスクではなく睡眠かもしれない
   - 気分が落ちての逃避：積み残しを見せると逃避が強まるおそれがある（先延ばしを感情調整として捉える見方に基づく推測）
   - → 見せる「現実」の中身を、場面ごとに変える必要があるかもしれない
2. 「飲み込まれている」をどう判定するか
   - iOSのScreen Time APIでは、使用時間が閾値を超えたことは検知できる。一方、リールの中身や見方は取得できないはず（要確認）
   - 判定材料は、実質的に時間と時刻に限られそう
3. 「現実」（やること）のデータの出どころ
   - カレンダーやタスクアプリから読み込むのか、アプリ内で宣言させるのか
   - 毎回手入力させる方式は「重くない」という条件と衝突する
4. 対象と当事者性のずれ
   - 本人が当事者として検証できるのは学生（勉強）の場面
   - 社会人を対象にする部分は推測にとどまる
   - 案：まず自分で検証し、社会人への拡張は仮説として扱う
